# 三指标家居任务实验

日期：2026-10-31。本轮测试固定多目标目录任务，不包含LLM搜索规划、任意自然语言或真机；视觉服务为真实已配置模型。

## 固定实验设计

六次全新仿真，各执行同一条编号2,3,4：背包挂墙检查→门关闭检查→厨房有水果的果盘检查→返回本次起点。

| 场景 | 背包 | 门 | 果盘 | 三项预期 |
|---|---|---|---|---|
| positive | hanging | closed | present | detected |
| negative | floor | open | empty | not_detected |

顺序事先固定为P,N,N,P,P,N，各3次；每次重新启动世界和初始化，不沿用上次任务的定位与记忆。使用固定代码/提示词/目标点；中途不调参数。预期由场景配置确定，不根据模型回答改标。

## 指标

1. **端到端任务成功率**：实际三次到点、检查结果逐项符合预期、返航步骤成功且最后定位相对任务起点误差≤0.35m/0.35rad，才计成功。程序SUCCEEDED不够；unknown、错误结论、缺失检查、导航或返航失败都失败。分母为实际尝试的实验轮次，计划6轮；启动技术失败保留。返航误差来自AMCL估计，不是物理真值精度。
2. **视觉有效判定率**：对图片可明确判断的实际观测，明确且符合预期的结果/可明确判断的图片数。unknown和误判均未通过。无图片与不可判断画面单列，不会因此把端到端失败剔除。图像清晰度由助手逐图复核，非盲评、非独立人工标注；未复核时指标为空。仅依据可见性，不根据模型答对与否选择分母。
3. **任务耗时**：perf_counter墙上时间，从提交检查命令到命令退出，含ROS客户端准备、图像采集、视觉API、保存报告、导航和返航；仿真启动、人工输入/确认等待在计时外，实验自动提交确认。失败样本保留。分别报告全部尝试、严格成功子集和正反场景的均值/中位数/最短/最长。额外最终位姿读取不计入任务时间。

## 环境与记录

使用独立ROS域80–85，Gazebo无GUI、无RViz；相机仍真实渲染，云端视觉真实计费。与用户同时打开GUI的时间不可直接比较。模型别名固定但远端权重版本无法锁定。未关闭工作区之外的后台服务，运行耗时包含实际网络和机器调度波动。

scripts/measure_household.py 复用现有check/MissionExecutor，不创建新的执行框架；protocol.json保存场景、预期、阈值、模型及业务代码散列。每轮保存启动日志、task.log、mission.json、图片、最终位姿与关闭状态。轮次逐次落盘，中途失败不删除或选择性重跑。

复现前在Linux桌面关闭自己之前的仿真，加载ROS工作区和本机密钥（不要打印密钥），然后：

```bash
source /opt/ros/jazzy/setup.bash
source install/local_setup.bash
unset ROBOPILOT_LLM_API_KEY
set -a
source robopilot.local.env
set +a
/usr/bin/python3 scripts/measure_household.py --output runs/metrics-new --base-domain 80
```

输出目录必须不存在，选用ROS域必须未被使用。使用云端VLM会上传仿真相机图像并产生用量。需要桌面图形环境供传感器软件渲染，但不打开GUI。

清晰度复核记录在输出目录clarity-labels.json，以trial-id/observation-id为键，包含clear和note。复核后重新汇总：

```bash
/usr/bin/python3 scripts/measure_household.py --output runs/metrics-new --summarize
```

仅6次、同一地图和同一套模型资产，是小样本重复实验；不得宣称泛化性能、独立视觉集准确率或稳定时延保证。raw输出与失败案例保留。

## 本轮结果

业务代码与运行器散列复核未变，6轮均按预定顺序记录，未替换失败样本。正例3次、反例3次；其中1次反例启动失败，实际提交5次任务、产生15张图片。

| 指标 | 结果 | 分母说明 |
|---|---|---|
| 端到端严格成功率 | **3/6 = 50.0%** | 含启动失败；程序SUCCEEDED但识别错也失败 |
| 视觉有效判定率 | **13/15 = 86.7%** | 15张实际图片均经助手复核可判断，非盲评；含1次误判、1次unknown |
| 任务墙上耗时 | **平均91.56秒，中位90.90秒** | 5次实际提交，包含识别失败任务，不含启动 |
| 耗时范围 | 88.29–95.55秒 | 没提交的启动失败不虚构0秒 |
| 严格成功子集耗时 | 平均92.52秒，3次 | 另列，不替代全部样本均值 |

逐轮：P成功93.728秒；N启动失败无任务时间；N成功95.546秒；P成功88.288秒；P背包误判89.352秒；N开门unknown90.902秒。五次实际提交均完成返航，误差在预注册阈值内。

视觉拆分：背包4/5，门4/5，果盘5/5。trial-05挂墙背包被判not_detected；trial-06开门图可辨却返回unknown，两者均计为视觉未通过。trial-02的3项检查未发生，不计入视觉分母，仍计入端到端失败。

耗时主要来自导航/返航，五次约81.8–86.9秒；三次图像/VLM检查合计约3.0–4.1秒，剩余是客户端准备、保存和进程开销。该拆分不是API纯网络延迟。

启动失败日志为Gazebo无法找到/加载世界文件；可能涉及启动文件准备时序，尚未证明根因。本轮没有在实验中修复或选择性重跑。下一轮优先修复启动依赖与背包/门的观测可靠性，沿用相同协议比较。
