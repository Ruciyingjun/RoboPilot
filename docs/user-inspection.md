# 用户自选检查

查看清单不需要启动仿真或配置密钥：

```bash
./robopilot tasks
```

当前支持：

1. 客厅工具箱是否存在。
2. 卧室背包是否挂在墙钩上。
3. 指定外门是否关闭。
4. 厨房果盘中是否有水果。
5. 客厅红色标记检查（本地颜色检测）。

## 交互操作

先在 Linux 桌面终端启动 ./robopilot sim-lite，等待 ready=true。另一个项目终端：

```bash
./robopilot check
```

输入编号组合，例如 2,3,4，或者：

```text
检查背包是否在墙上挂着、门是否关闭、果盘是否在厨房
```

系统展示地点、完整检查要求和返航步骤；输入 y 或 是 才开始。其他回答、退出或EOF不会发送目标。机器人移动后不要重新初始化出生位姿。

只预览，不启动机器人和云服务：

```bash
./robopilot check --instruction '检查背包是否挂在墙上、门是否关闭、果盘是否在厨房' --preview
```

也可直接传编号：./robopilot check --instruction '3,2'，仍需交互确认。

## 设计与边界

- 目录匹配为有限中文句式与编号解析，不调用LLM规划。按用户输入顺序生成同一套结构化计划，校验后复用MissionExecutor；所有选择自动加本次起点返航。
- 未知对象、未支持地点、条件分支、否定要求、重复项目都拒绝整条指令，不能把无法理解的部分静默丢掉。请用编号重选，或使用清单中的完整说法。
- 果盘任务实际检查“厨房果盘内有水果”，不仅是有一个盘；预览会明确说明。背包与门同样检查关系/状态，不是单纯存在。
- 工具箱、背包、门和果盘的实际检查会上传相机图片并产生API费用；清单、预览和取消不调用模型。纯红色目标检查为本地处理。
- 这是可预览的静态多目标检查入口；search/search-toolbox仍是原来的受约束工具反馈循环，不宣称二者相同。
- 沿用固定地点与当前地图；不是开放世界搜索，不支持抓取、开关门、其他房间的同名物品或任意自然语言。
- 报告保留原始输入、实际检查结果和图片；任务SUCCEEDED只表示执行完成，不等于每个条件都满足。
